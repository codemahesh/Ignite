- **This Next.js version has genuinely different internals from older training data** — it ships its own `AGENTS.md`/`CLAUDE.md` pointing at `node_modules/next/dist/docs/`. Those files are auto-regenerated by `next dev` itself and are meant to be committed (comment in the file says so) — don't delete them, don't be surprised they exist.
- `frontend/src/lib/api.ts` — exports `API_BASE_URL` from `process.env.NEXT_PUBLIC_API_BASE_URL` (fallback `http://localhost:8010`). Import this anywhere the frontend needs to call the backend — don't read `process.env.NEXT_PUBLIC_API_BASE_URL` directly elsewhere (Next.js only inlines *literal* `process.env.NEXT_PUBLIC_*` references at build time, not indirected ones, so centralizing it in one file that does the literal reference is required, not just tidy).
- `frontend/src/app/page.tsx` — client component (`"use client"`), fetches `${API_BASE_URL}/health` on mount, shows "Checking backend..." → "Backend healthy" / "Backend unreachable: ...".
- `frontend/src/app/layout.tsx` — title/description updated to "Company Brain".
- `frontend/.env.example` (committed) + `.env.local` (gitignored) — `NEXT_PUBLIC_API_BASE_URL=http://localhost:8010`.

## Local dev ports — read before running anything

**Three unrelated Docker-based projects are already running on this machine and occupy the "obvious" ports.** Confirmed occupied: 3000 (Docker container, another project's frontend), 5432–5435 (other Postgres containers), 8000 (another project's API).

- Backend: **8010** (see memory/BE-1.md).
- Frontend: **3010**. `frontend/package.json`'s `dev`/`start` scripts are hardcoded with `-p 3010` — **do not run `next dev` without that flag**, and don't rely on Next.js picking an open port automatically.

**Gotcha discovered and worth repeating:** backend's `.env` also defines `PORT=8010`. If you `source backend/.env` and then run a frontend npm command **in the same shell session**, the exported `PORT` env var leaks into `npm run dev` and Next.js will honor `$PORT` over its own default — it tried to bind 8010 too, colliding with the backend. **Always start backend and frontend commands in separate shell/Bash tool invocations**, never chained with `&&` in one command that also sources `backend/.env`. The `-p 3010` flag in package.json is a second line of defense but doesn't fully prevent this if something later removes that flag.

## How to run it

```
cd frontend
npm run dev
```
→ http://localhost:3010 (backend must already be running on 8010 for the health check to go green).
